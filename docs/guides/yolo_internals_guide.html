This is the DEEP guide - how YOLO actually thinks inside. No need to write code. This is to understand the logic - why YOLO, grids, tensors, backbone neck head.
First - Why YOLO? What does "You Only Look Once" even mean?
The name is the whole idea. YOLO looks at the full image only ONE time (one pass) and predicts every box in that single look. Thats why it is fast enough for live video.
Before YOLO, detectors did NOT work like this. They used to take a small window and slide it all over the image, running a CNN again and again on each little region, checking "object here? object here? object here?" - thousands of CNN runs for one image. Very slow, no chance for real-time.
Old way (before YOLO) YOLO way
Slide a window / propose many regions Cut image into a grid once
Run CNN thousands of times per image Run CNN ONE time per image
Slow, heavy, not live Fast, real-time, many cameras
This is exactly why our multi-camera vehicle project uses YOLO - one look per frame means we can handle live feeds. The GRID method is what makes "one look" possible. Next we see how that grid is built.
Now show me how the grid is actually built. 640x640x3 to 160x160... how?
The image enters as 640 x 640 with 3 channels (BGR). Then layer by layer the network shrinks the floor and grows the channels. It does not jump straight to 160, it halves step by step.
640 x 640 x 3      # input image (3 color channels)
   |  (halve)
320 x 320 x 32     # floor halved, channels grew
   |  (halve)
160 x 160 x 48     # floor halved again, more channels
   |  ... keeps going down to 20 x 20 later
Each halving step takes a small group of NEAR pixels (a 2x2 block = 4 neighbours) and squeezes them into ONE new cell. So detail floor shrinks, but we add more channels to store richer info about that squeezed area.
Note: exact channel numbers (32, 48, 64...) depend on model size n/s/m/l/x. The number is not important, the IDEA is: floor down, channels up.
But how does 4 near pixels become 1? Who decides the new numbers?
A small filter sits on those 4 (actually a small patch) neighbour pixels, multiplies them by some weights, and adds up to make the one new number. That weight set is what decides how neighbours combine.
And here is the key point you were asking - those weight values are TRAINED values. During COCO training the model saw thousands of images and slowly fixed these weights to good numbers. We do NOT calculate them. They already sit inside yolo11l.pt. We just load and use.
What did these trained weights learn to detect?
Layer depth What its filters learned
1st layers (shallow) simple things - edges, lines, corners, colors
middle layers parts - a wheel curve, a window shape, a headlight
deep layers full concept - "this whole thing is a car"
So the FIRST layer just finds edges and lines. The NEXT layer takes those edges and joins them into bigger features, and so on. Small patterns build into big patterns as we go deeper. Thats the whole learning stack.
What is stride? People keep saying it.
Stride = the step size the filter jumps as it slides. Stride 1 means move 1 pixel each step (floor stays same size). Stride 2 means jump 2 pixels each step, so it skips and the output floor becomes HALF. Thats how downsampling happens.
There is also a total stride from the input. It means "how many original pixels does one cell now stand for".
Feature floor Total stride One cell = how many input pixels
320 x 320 2 2 x 2 area
160 x 160 4 4 x 4 area
80 x 80 8 8 x 8 area
40 x 40 16 16 x 16 area
20 x 20 32 32 x 32 area
So bigger stride = smaller grid = each cell covers a bigger chunk of the real image. Remember this, it comes back when we pick which grid detects small vs big objects.
Ok now the tensor / cube part. I imagine image as a cube.
Your cube imagination is correct, just make it exact. A tensor is only a box of numbers. The number of directions (axes) it has, is its dimension.
Tensor Shape Think of it as
1D (5) a single row of numbers (a line)
2D (H, W) a grey image, one number per pixel (a sheet)
3D (C, H, W) a color image = your CUBE. C sheets stacked
4D (N, C, H, W) many cubes together (a batch of images)
So one color image is a 3D cube. Height and Width is the floor, and C (channels) is how tall the stack is. For a normal photo C=3 (the BGR sheets). Deeper in the network the same cube has a small floor but a very tall channel stack.
Note: OpenCV shows image as (H, W, C). PyTorch/YOLO uses (C, H, W). Same cube, just axis order different. Dont get confused.
Then what is this 4D tensor, why one extra?
Because computer never process one image alone, it process a BATCH (many images at once, faster on GPU). So we stack many cubes and get 4D.
Axis Letter Meaning
1st N batch - how many images together
2nd C channels - how many sheets in each cube
3rd H height of the cube floor
4th W width of the cube floor 
# one image cube
image = (3, 640, 640)      # 3 channels, 640x640 floor

# batch of 8 images = 4D tensor
batch = (8, 3, 640, 640)   # N=8, C=3, H=640, W=640
So remember simply: 4D tensor = a pile of image cubes. N is just how many cubes in the pile. Everything inside YOLO travels as this 4D shape.
And channels - only colors, or something else?
At the START yes, channels are colors (3 = B,G,R). But INSIDE the network channels stop being colors and become FEATURES.
A feature is just "some pattern the layer found" - an edge, a wheel shape, a headlight shape. Each channel is one detector of one pattern. So a cube with C=256 means 256 different pattern-sheets stacked.
Key mind-shift: deeper we go, channels are NOT colors anymore, they are learned features/patterns.
Now shallow vs deep - take me down till 20x20.
This is the core logic, get it clean. As the cube goes DEEPER, two things happen together - floor keeps shrinking, meaning keeps getting stronger.
Stage Floor (H x W) Channels Detail (position) Feature strength (meaning)
Shallow (early) BIG (160x160 / 80x80) few (48...) HIGH - sharp, exact position WEAK - only edges, colors (dumb)
Middle medium (40x40) more (512) medium medium - shapes, parts
Deep (late) SMALL (20x20) many (1024) LOW - blurry position, coarse STRONG - "this is a car" (smart)
Correct sentence to remember: shallow = sharp detail but dumb. deep = smart meaning but blurry. The cube ends at 20x20 with a huge channel stack (like 1024).
At 20x20 with 1024 channels - what do those 1024 actually represent?
Very good question, this is the heart. At 20x20 there are only 400 cells. But each cell now carries 1024 numbers stacked on it. Those 1024 numbers are like 1024 answers to 1024 learned questions about that spot.
Imagine for one cell the 1024 channels silently answer things like:
channel 1   -> how much "wheel-ness" is here?
channel 2   -> how much "metal surface"?
channel 3   -> how much "car-roof shape"?
channel 4   -> how much "headlight"?
...                     (up to 1024 learned patterns)
channel 1024 -> how much "windscreen curve"?
So one cell is no longer a color pixel - it is a rich 1024-length description (a fingerprint) of "what kind of object sits around here". Thats why deep = smart. The model can now say "this fingerprint looks like a car". But because the floor is only 20x20, it lost the sharp position, and small far objects already vanished at this size.
1024 channels = 1024 learned feature-answers per cell. Rich meaning, poor position. Hold this thought - it explains why we need the neck next.
So if deep lost position and small objects - how do we fix it? The neck?
Exactly. The problem: the deep 20x20 grid is smart but it dropped small objects and exact position. Meanwhile the shallow 80x80 and 40x40 grids STILL have those small objects and sharp position - but they are dumb (weak features).
So neither grid alone is good. The NECK's job is to make all three grids share their strengths so no feature gets dropped. It connects 20x20, 40x40 and 80x80 and mixes them.
Simple line: deep grid has the brain, shallow grids have the eyes for small/near-exact stuff. Neck joins brain + eyes on all three grids.
Give me FPN and PAN full form and how they take the features (no heavy math).
The neck is made of two flows, running in opposite directions:
Flow Full form Direction What it carries (simple)
FPN Feature Pyramid Network Top -> Down (20 -> 40 -> 80) takes STRONG meaning from the deep 20x20 grid, blows it up bigger, and pours it into 40x40 and 80x80 so those sharp grids also become smart
PAN Path Aggregation Network Bottom -> Up (80 -> 40 -> 20) takes SHARP position from the shallow 80x80 grid, shrinks it down, and pushes it into 40x40 and 20x20 so those smart grids also get exact position
How they "take" features is simple: FPN upsamples the small deep grid (makes it bigger) and merges it onto the bigger grid. PAN downsamples the big shallow grid (makes it smaller) and merges it onto the smaller grid. Merge just means put the two feature stacks together. No formula needed - just resize and combine.
After FPN + PAN, all three grids (80, 40, 20) are now GOOD - each has strong meaning AND sharp position. Nothing important is dropped. Thats the entire purpose of the neck.
Now the 3 body parts and the 3 grids together.
The whole YOLO body is only 3 parts, like a factory line.
Part Job (simple) What it makes
1. Backbone Look at image, extract features, downsample. Cube shrinks, channels grow. 3 feature cubes: 80x80, 40x40, 20x20
2. Neck (FPN+PAN) Mix the 3 cubes so features travel between layers and nothing drops. 3 improved cubes (same sizes)
3. Head Read each grid cell and predict box + class. final boxes, class, confidence
And the 3 grids split the work by object size (because of stride):
Grid Stride Best for
80 x 80 8 SMALL objects (far vehicle)
40 x 40 16 MEDIUM objects
20 x 20 32 LARGE objects (near truck)
Flow in one line: Image -> Backbone -> Neck -> Head -> boxes. Backbone sees, Neck mixes, Head decides.
Extra: inside the backbone there are names like Conv, C2f, SPPF. What are these?
These are just NAMES of the small building blocks stacked inside the backbone. Think of the backbone like a line of little machines, one after another, image passes through each. You do NOT need to understand them for our project - just know they exist so no name confuses you.
Image
  |
 Conv     # slides filters, finds edges/patterns, downsamples
  |
 C2f      # a feature-mixing block (helps info flow)
  |
 Conv
  |
 C2f
  |
 SPPF     # last block - looks at many scales so big & small both caught
  |
 -> Neck (FPN + PAN) -> Head
Block Basic idea (thats enough)
Conv Convolution layer - slides filters, finds patterns, and does the downsampling (stride)
C2f / C3k2 A feature-mixing block. Just helps features flow better. (C2f in v8, C3k2 in v11 - different name, same purpose)
SPPF Spatial Pyramid Pooling Fast - looks at the image at many scales at once, so near AND far objects get noticed
Do NOT get stuck on these names. For our project we never touch them, YOLO already has them built inside. Just remember: Backbone = a stack of Conv + C2f blocks ending with SPPF. Thats all you need.
Last - what does the head actually output?
Head output is also a tensor. For each of the 3 grids, the head looks at every cell and writes down the box numbers + the class scores.
# one scale head output (rough idea, COCO = 80 classes)
output = (N, 84, H, W)     # 84 = 4 box values + 80 class scores, per cell

80x80 grid -> lots of small-object predictions
40x40 grid -> medium-object predictions
20x20 grid -> large-object predictions
Then YOLO automatically cleans it up - drops the low-confidence ones and removes duplicate boxes sitting on the same object. What survives is the clean final boxes you used in code (box.xyxy, box.cls, box.conf).
Note: this auto-cleanup has a name (NMS) but for our project you do NOT need to understand it. YOLO does it for us and just hands over the final boxes.
Note: YOLO11 is "anchor-free" - each cell predicts the box directly. Old YOLO used pre-set "anchor box" templates. No anchor math needed for us.
Give me the whole story in one shot so it sticks.
Full journey of one image, top to bottom:
1. Image in as 4D tensor         (N, 3, 640, 640)   # pile of cubes
2. BACKBONE (trained filters)    floor 640 -> 20, channels 3 -> 1024
   shallow=edges, deep=concepts  gives 3 grids: 80x80, 40x40, 20x20
3. NECK  FPN (top-down meaning)   + PAN (bottom-up position)
   all 3 grids now smart+sharp    nothing dropped
4. HEAD reads every cell          predicts box(4) + class(80) per cell
5. Auto cleanup                  drop weak + duplicate boxes
6. OUT -> box.xyxy, box.cls, box.conf   # the answer we use in code
Core facts to lock in your memory
- YOLO = You Only Look Once. One CNN pass per image using a grid. Before YOLO, detectors slid a window and ran CNN thousands of times per image - too slow for live.
- The image shrinks step by step: floor halves (near pixels merge), channels grow. The merge weights are TRAINED values, already inside the .pt file.
- First layers learn edges/lines, deeper layers join them into parts, deepest into full objects.
- Stride = step size / how many input pixels one cell stands for. Big stride = small grid = big objects.
- Image = 3D cube (C,H,W). Batch = 4D tensor (N,C,H,W). N = how many cubes piled.
- Channels start as colors (3) but become learned FEATURES deeper in.
- Shallow = sharp but dumb. Deep = smart but blurry. At 20x20, the 1024 channels = 1024 learned feature-answers per cell (a rich fingerprint of the object).
- Deep grid dropped small objects + position, so NECK connects 80/40/20. FPN (Feature Pyramid Network) carries meaning top-down, PAN (Path Aggregation Network) carries position bottom-up. Both just resize + merge. Nothing drops.
- Backbone sees, Neck mixes, Head decides. Head outputs box+class per cell, then YOLO auto-cleans (drops weak + duplicate boxes) to give final boxes. NMS is the name of this step but no need to go deep for our project.
- YOLO11 is anchor-free. No anchor math needed for us.
