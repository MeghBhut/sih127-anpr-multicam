TEAM PLAN - how all 6 of us build ONE project together on GitHub without breaking each other. Read this fully before coding. This teaches us OOP + Git + teamwork at once.
Should we write the whole project in one big file?
NO. If all 6 of us edit one file, every time we push to GitHub it becomes a merge conflict fight (Git cant join 6 people editing the same lines). That kills teamwork.
Instead we split into many files - one class per file, one file owned by one person. main.py just imports them and calls them. This is called modular OOP design. Because each person edits a DIFFERENT file, Git merges everyone's work with almost zero conflict. Nobody can break another's part.
Rule: You only edit YOUR file. You never touch someone else's file. If you need a change in their file, you ASK them.
How do the parts connect if they are separate files?
By a shared CONTRACT. Before anyone codes, we all agree on the exact "packet" that travels between modules. Everyone builds to this same shape, so the parts snap together like Lego. This is the MOST important step.
# THE CONTRACT - one detected vehicle is always this dictionary

PERSON 1 - Camera Input (camera.py)
Your job: open any source (webcam number, video file, or CCTV rtsp link) and hand out frames. Nothing else.
import cv2 as cv

class CameraManager:
    def __init__(self, source, camera_id):
        self.cap = cv.VideoCapture(source)   # 0 / "video.mp4" / "rtsp://..."
        self.camera_id = camera_id

    def read(self):
        return self.cap.read()               # returns (ret, frame)

    def release(self):
        self.cap.release()
Give out: (ret, frame). Thats your only output. Learn from the OpenCV guide.
PERSON 2 - Detect + Track (detector.py)
Your job: take a frame, run YOLO tracking, return a LIST of contract packets (one per vehicle). This is the heart module.
from ultralytics import YOLO

class VehicleDetector:
    def __init__(self, model_path, vehicle_classes):
        self.model = YOLO(model_path)
        self.vehicle_classes = vehicle_classes    # [2,3,5,7]

    def detect_and_track(self, frame, camera_id):
        results = self.model.track(frame, persist=True,
                                   tracker="botsort.yaml", verbose=False)
        detections = []
        for r in results:
            for box in r.boxes:
                if box.id is None:
                    continue
                cls = int(box.cls[0])
                if cls not in self.vehicle_classes:
                    continue
                detections.append({
                    "track_id": int(box.id[0]),
                    "xyxy": tuple(map(int, box.xyxy[0])),
                    "name": self.model.names[cls],
                    "conf": float(box.conf[0]),
                    "plate": None,
                    "camera_id": camera_id,
                })
        return detections      # list of contract packets
Important: for MULTI camera, make ONE VehicleDetector object PER camera. If all cameras share one detector the track IDs get mixed. One camera = one detector object.

PERSON 4 - Track Database (database.py)
Your job: remember every vehicle. For each (camera_id, track_id) keep its plate and its list of positions. This memory is what makes counting and pathing possible.
class TrackDatabase:
    def __init__(self):
        self.tracks = {}    # key = (camera_id, track_id)

    def update(self, detections):
        for det in detections:
            key = (det["camera_id"], det["track_id"])
            if key not in self.tracks:
                self.tracks[key] = {"plate": None, "positions": []}
            # center point of the box
            x1, y1, x2, y2 = det["xyxy"]
            cx, cy = (x1 + x2) // 2, (y1 + y2) // 2
            self.tracks[key]["positions"].append((cx, cy))
            if det["plate"]:
                self.tracks[key]["plate"] = det["plate"]

    def all_tracks(self):
        return self.tracks
Take in: list of detections. Give out: the full memory of all tracks. Person 5 will use this to draw the map.

PERSON 6 - Main + Config (main.py + config.py)
Your job: you are the glue. You import all 5 modules, create their objects, and run the main loop that passes data from one to the next. You also hold all settings in config.py so nobody hardcodes numbers.
# ---------- config.py (settings everyone reads) ----------
CAMERA_SOURCES = [0]           # or ["cam1.mp4", "cam2.mp4"]
MODEL_PATH = "yolo11l.pt"
VEHICLE_CLASSES = [2, 3, 5, 7] # car, motorcycle, bus, truck

# ---------- main.py (wires all parts) ----------
import cv2 as cv
import config
from camera import CameraManager
from detector import VehicleDetector
from plate_reader import PlateReader
from database import TrackDatabase
from visualizer import Visualizer

# build objects (one detector per camera)
cameras   = [CameraManager(src, i) for i, src in enumerate(config.CAMERA_SOURCES)]
detectors = [VehicleDetector(config.MODEL_PATH, config.VEHICLE_CLASSES) for _ in cameras]
plate     = PlateReader()
db        = TrackDatabase()
viz       = Visualizer()

while True:
    for cam, det in zip(cameras, detectors):
        ret, frame = cam.read()
        if not ret:
            continue

        detections = det.detect_and_track(frame, cam.camera_id)   # Person 2

        for d in detections:
            d["plate"] = plate.read(frame, d["xyxy"])              # Person 3

        db.update(detections)                                     # Person 4
        frame = viz.draw_boxes(frame, detections)                # Person 5
        viz.update_map(db.all_tracks())                          # Person 5

        cv.imshow(f"Camera {cam.camera_id}", frame)

    if cv.waitKey(1) & 0xFF == ord('q'):
        break

for cam in cameras:
    cam.release()
cv.destroyAllWindows()
See how clean main.py is? It never knows HOW each part works inside, it only calls the agreed method names. Thats the power of the contract.
Now the GitHub team workflow - how we all push without breaking each other
How do we set up the folder and GitHub?
Final folder looks like this:

One person (Person 6) makes the GitHub repo and pushes this empty skeleton first (all files with just the class stubs above). Then everyone clones it.
What is the daily git steps for each person?
Everyone follows the SAME 6 steps. Never code directly on main branch.
git clone <repo-link>             # first time only
git checkout -b feature/camera    # make YOUR own branch (own name)

# ... edit ONLY your file ...

git add camera.py                 # add only your file
git commit -m "camera: added CameraManager read()"
git push origin feature/camera    # push your branch

# then on GitHub website: open a Pull Request -> team reviews -> merge to main
Before starting work each day, pull the latest main so you have everyone's merged work:

git checkout main

git pull origin main

git checkout -b feature/camera-day2 # new small branch for new work

How do we FORCE that no one can edit another's file?
Two things. First a CODEOWNERS file that maps each file to its owner. Put it in the repo root.
# CODEOWNERS file
camera.py         @teammate1
detector.py       @teammate2
plate_reader.py   @teammate3
database.py       @teammate4
visualizer.py     @teammate5
main.py           @teammate6
config.py         @teammate6
Second, on GitHub go to Settings -> Branches -> add a rule on main -> tick "Require review from Code Owners" and "Require a pull request before merging". Now if anyone's PR touches a file they dont own, GitHub blocks the merge until the real owner approves. Thats the enforcement you wanted.
Note: CODEOWNERS needs real GitHub usernames (with @). branch protection rules are set by the repo owner (Person 6) once.
